# اتوماسیون ایمیل تبلیغاتی به شرکت‌ها

منطقه و حوزه کاری را می‌دهید؛ سیستم شرکت‌های آن منطقه را روی نقشه پیدا می‌کند، ایمیل عمومی هر شرکت را از سایت خودش درمی‌آورد و ایمیل تبلیغاتی شما را با سرعت کنترل‌شده از SMTP دامنه سایتتان برایشان می‌فرستد.

```
web/     پنل مدیریت (Next.js)            http://localhost:3000
engine/  موتور پایتون (FastAPI + SQLite)  http://localhost:8000
```

## راه‌اندازی در یک نگاه

| مرحله | کجا | چه چیزی لازم است | نتیجه |
|---|---|---|---|
| ۱. تست روی کامپیوتر خودتان | ویندوز | Python و Node.js | همه چیز کار می‌کند ولی هیچ ایمیلی واقعاً ارسال نمی‌شود |
| ۲. تنظیم فرستنده | `engine/.env` | نام، ایمیل، سایت و پاورقی شما | ایمیل‌ها و پیش‌نمایش‌ها با اطلاعات واقعی شما |
| ۳. کلیدهای اختیاری | `engine/.env` | `GOOGLE_PLACES_API_KEY`، `ANTHROPIC_API_KEY` | شرکت‌های بیشتر، ترجمه بهتر کلیدواژه‌ها |
| ۴. ارسال آزمایشی | `engine/.env` | SMTP دامنه سایت، `MAIL_MODE=redirect` | ایمیل‌ها فقط به صندوق خودتان می‌آیند |
| ۵. ارسال واقعی | DNS دامنه + `engine/.env` | SPF، DKIM، DMARC و `MAIL_MODE=live` | ارسال به شرکت‌ها با سرعت کنترل‌شده |
| ۶. سرور | VPS لینوکس | دامنه یا زیردامنه، Nginx | پنل همیشه روشن و لینک لغو اشتراک از بیرون در دسترس |

مرحله ۱ تا ۴ را می‌توانید روی کامپیوتر خودتان انجام دهید. برای مرحله ۵ عملاً سرور لازم است، چون ارسال چند روز طول می‌کشد (گرم‌کردن تدریجی) و لینک لغو اشتراک داخل ایمیل‌ها باید همیشه باز شود. جزئیات هر مرحله در بخش‌های پایین آمده است.

## اجرا (حالت تست)

پیش‌نیاز: Python 3.12+ و Node.js 20+

روی `dev.bat` دوبار کلیک کنید. این فایل محیط پایتون را می‌سازد، وابستگی‌ها را نصب می‌کند، فایل `engine/.env` را از روی نمونه می‌سازد و هر دو بخش را اجرا می‌کند.

در حالت پیش‌فرض (`MAIL_MODE=file`) **هیچ ایمیلی واقعاً ارسال نمی‌شود**؛ هر ایمیل به‌صورت فایل `.eml` در `engine/outbox/` ذخیره می‌شود و می‌توانید با Outlook یا Thunderbird بازش کنید.

اجرای دستی:

```bash
cd engine && .venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
cd web && npm run dev
```

## زبان پنل

کل پنل به سه زبان فارسی، انگلیسی و آلمانی در دسترس است. زبان را از پایین منوی کناری (یا بالای صفحه در موبایل) عوض کنید؛ انتخاب شما در مرورگر ذخیره می‌شود. جهت صفحه (راست‌به‌چپ یا چپ‌به‌راست)، تاریخ‌ها، اعداد، پیام‌های خطا، گزارش جستجوها، نام دسته‌ها و خروجی Excel همه به زبان انتخابی نمایش داده می‌شوند.

- متن‌های پنل در `web/lib/i18n/` هستند (`fa.ts` مرجع است و `en.ts` و `de.ts` باید همان کلیدها را داشته باشند؛ اگر کلیدی جا بیفتد TypeScript خطا می‌دهد).
- موتور پایتون پیام‌ها را به‌صورت کد برمی‌گرداند (`engine/app/i18n/messages.py`) و پنل آن‌ها را ترجمه می‌کند.
- زبان پنل با زبان ایمیل‌ها فرق دارد: زبان هر ایمیل در تنظیمات همان کمپین انتخاب می‌شود.

## روند کار

1. **پیدا کردن شرکت‌ها**: منطقه (مثلاً «اصفهان» یا «منطقه ۶ تهران») و حوزه کاری را انتخاب کنید. منابع:
   - OpenStreetMap (رایگان، بدون کلید)
   - Google Places (اختیاری، با `GOOGLE_PLACES_API_KEY` در `engine/.env`؛ نتایج کامل‌تر — بخش [فعال‌سازی Google Places](#فعالسازی-google-places-اختیاری))

   برای هر شرکتی که سایت دارد، صفحه اصلی و صفحات «تماس با ما / درباره ما» خوانده می‌شود، ایمیل‌ها استخراج و رتبه‌بندی می‌شوند (ایمیل هم‌دامنه سایت و آدرس‌هایی مثل info@ و sales@ در اولویت‌اند) و رکورد MX دامنه بررسی می‌شود. آدرس صفحه‌ای که ایمیل در آن پیدا شده کنار هر شرکت ذخیره می‌شود.
2. **شرکت‌ها**: لیست را ببینید، ویرایش کنید، از Excel/CSV وارد کنید یا خروجی Excel بگیرید.
3. **کمپین**: موضوع و متن HTML را بنویسید (متغیرهایی مثل `{{ company_name }}`)، پیش‌نمایش ببینید، ایمیل تست بفرستید و ارسال را شروع کنید.
4. **لیست عدم ارسال**: هر کس روی لینک لغو اشتراک بزند یا ایمیلش برگشت بخورد، خودکار اینجا می‌آید و دیگر هرگز ایمیل نمی‌گیرد.

حوزه‌های کاری در `engine/app/modules/discovery/categories.py` تعریف شده‌اند و می‌توانید دسته جدید اضافه کنید.

### کلیدواژه به هر زبانی

کلیدواژه را به هر زبانی بنویسید (مثلاً «آسانسور»). کشور منطقه تشخیص داده می‌شود و کلیدواژه خودکار به زبان آن کشور و انگلیسی ترجمه می‌شود (مثلاً Aufzug و Elevator برای آلمان). کلمه‌هایی که جستجو شدند روی کارت هر جستجو نمایش داده می‌شوند.

- بدون تنظیم اضافه: سرویس رایگان MyMemory (فقط ترجمه مستقیم).
- با `ANTHROPIC_API_KEY` در `engine/.env`: Claude کلمات مشابه و ریشه کلمات را هم اضافه می‌کند (مثلاً Notfall، Rettungsdienst، emergency) که نتیجه را خیلی بیشتر می‌کند.

### فعال‌سازی Google Places (اختیاری)

بدون این کلید هم همه چیز کار می‌کند و فقط OpenStreetMap جستجو می‌شود. گوگل معمولاً شرکت‌های بیشتری پیدا می‌کند، مخصوصاً آن‌هایی که روی نقشه‌های آزاد ثبت نشده‌اند.

> **هزینه:** ماهی ۱۰۰۰ درخواست رایگان، بعد از آن حدود ۳۵ دلار برای هر ۱۰۰۰ درخواست (چون سایت و تلفن شرکت را می‌گیریم، درخواست‌ها جزو Text Search Enterprise حساب می‌شوند). هر جستجو ۲ یا ۳ عبارت دسته به‌علاوه حداکثر ۴ کلیدواژه را جستجو می‌کند و هر کدام ۱ تا ۳ صفحه نتیجه دارد، یعنی حدود ۳ تا ۲۰ درخواست؛ پس سهم رایگان برای ده‌ها جستجو در ماه کافی است. قیمت‌ها را گوگل گاهی تغییر می‌دهد؛ قبل از فعال‌سازی [صفحه قیمت رسمی](https://developers.google.com/maps/billing-and-pricing/pricing) را ببینید.
>
> **کارت بانکی:** حتی برای سهم رایگان، ثبت کارت بانکی بین‌المللی لازم است. کارت‌های ایرانی پذیرفته نمی‌شوند و Google Cloud به‌خاطر تحریم‌ها در ایران ارائه نمی‌شود؛ کلید فقط با حساب و کارتی از کشوری که گوگل پشتیبانی می‌کند ساخته می‌شود.

1. وارد [console.cloud.google.com](https://console.cloud.google.com) شوید و از بالای صفحه یک **پروژه جدید** بسازید.
2. از منوی **Billing** یک حساب پرداخت بسازید، کارت را ثبت کنید و آن را به پروژه وصل کنید.
3. از مسیر **APIs & Services ← Library** عبارت **Places API (New)** را جستجو و **Enable** کنید (نسخه Legacy را نه).
4. از مسیر **APIs & Services ← Credentials ← Create credentials ← API key** کلید را بسازید.
5. روی کلید ساخته‌شده بزنید و آن را محدود کنید:
   - **API restrictions**: فقط Places API (New)
   - **Application restrictions**: روی سرور، فقط IP سرور (در حالت تست روی کامپیوتر خودتان می‌توانید خالی بگذارید)
6. جلوی هزینه ناخواسته را بگیرید:
   - **APIs & Services ← Places API (New) ← Quotas**: سقف درخواست روزانه را مثلاً ۳۳ بگذارید (حدود ۱۰۰۰ در ماه)
   - **Billing ← Budgets & alerts**: یک بودجه کم (مثلاً ۵ دلار) با هشدار ایمیلی بسازید
7. کلید را در `engine/.env` بگذارید و موتور را دوباره اجرا کنید:
   ```
   GOOGLE_PLACES_API_KEY=AIza...
   ```
8. در صفحه «پیدا کردن شرکت‌ها» تیک «جستجو در Google Maps هم انجام شود» فعال می‌شود. در گزارش هر جستجو تعداد نتایج گوگل جدا نوشته می‌شود؛ اگر کلید مشکل داشته باشد خطای گوگل همان‌جا نمایش داده می‌شود و جستجو با نتایج OpenStreetMap ادامه پیدا می‌کند.

### قالب‌ها و زبان ایمیل

۲۷ قالب آماده (۹ نوع × فارسی، انگلیسی، آلمانی) در بخش «قالب‌های ایمیل» هست. زبان هر کمپین جهت متن (راست‌به‌چپ یا چپ‌به‌راست)، پاورقی لغو اشتراک و صفحه لغو اشتراک را به همان زبان تعیین می‌کند. `SENDER_WEBSITE` و در صورت تمایل `SENDER_LOGO_URL` را در `engine/.env` پر کنید تا دکمه‌ها و سربرگ قالب‌ها درست نمایش داده شوند.

## رفتن به ارسال واقعی

1. در `engine/.env` مقادیر `SMTP_*`، `FROM_EMAIL`، `FROM_NAME` و `SENDER_FOOTER` را پر کنید.
2. اول `MAIL_MODE=redirect` و `TEST_RECIPIENT=ایمیل خودتان` بگذارید و یک کمپین کوچک اجرا کنید تا ایمیل‌ها را در صندوق خودتان ببینید.
3. **قبل از `MAIL_MODE=live` حتماً DNS دامنه را تنظیم کنید**؛ بدون این‌ها ایمیل‌ها مستقیم به اسپم می‌روند:
   - **SPF**: رکورد TXT روی دامنه، مثلاً `v=spf1 a mx include:<سرور ایمیل هاست> ~all`
   - **DKIM**: از پنل هاست (cPanel → Email Deliverability) کلید DKIM را فعال و رکوردش را در DNS ثبت کنید
   - **DMARC**: رکورد TXT روی `_dmarc.yoursite.ir`، مثلاً `v=DMARC1; p=none; rua=mailto:info@yoursite.ir`
4. `PUBLIC_BASE_URL` باید آدرس عمومی پنل باشد تا لینک لغو اشتراک از بیرون باز شود.

### توصیه‌های ارسال

- «گرم‌کردن تدریجی» را روشن نگه دارید: روز اول ۵۰ ایمیل و هر روز دو برابر تا سقف روزانه. دامنه تازه که یک‌باره ۲۰۰۰ ایمیل بفرستد بلاک می‌شود.
- فاصله بین ایمیل‌ها را کمتر از ۲۰ ثانیه نکنید. محدودیت ساعتی هاست اشتراکی خود را هم بپرسید (معمولاً ۱۰۰ تا ۵۰۰ در ساعت).
- متن کوتاه، شخصی‌سازی‌شده و بدون عکس‌های سنگین بهتر تحویل داده می‌شود.
- لینک لغو اشتراک و اطلاعات فرستنده همیشه به پاورقی اضافه می‌شوند؛ آن‌ها را حذف نکنید.

## ارسال به شرکت‌های آلمان و اروپا

طبق قانون رقابت آلمان (UWG §7) و GDPR، ارسال ایمیل تبلیغاتی حتی به شرکت‌ها معمولاً **رضایت قبلی** گیرنده را لازم دارد و جریمه آن می‌تواند سنگین باشد. قبل از کمپین گسترده در آلمان با یک مشاور حقوقی مشورت کنید. حداقل‌ها: اطلاعات کامل حقوقی فرستنده (Impressum) در `SENDER_FOOTER`، لینک لغو اشتراک (خودکار اضافه می‌شود)، و ایمیل‌های شخصی و کم‌تعداد به‌جای ارسال انبوه.

## انتقال به سرور

یک VPS لینوکس (مثلاً Ubuntu، ۱ هسته و ۱ تا ۲ گیگ رم کافی است) و یک زیردامنه مثل `panel.yoursite.ir` که به IP سرور اشاره کند.

1. **نصب پیش‌نیازها**: Python 3.12+، Node.js 20+، Nginx و certbot.
2. **کپی پروژه** روی سرور (مثلاً در `/opt/etmita-automotion`).
3. **موتور**:
   ```bash
   cd engine && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
   cp .env.example .env
   ```
   در `engine/.env` این‌ها را پر کنید: `MAIL_MODE`، `SMTP_*`، `FROM_EMAIL`، `FROM_NAME`، `SENDER_WEBSITE`، `SENDER_FOOTER`، `PUBLIC_BASE_URL=https://panel.yoursite.ir` و یک `API_KEY` طولانی و تصادفی.
4. **پنل**:
   ```bash
   cd web && npm ci && npm run build
   cp env.local.example .env.local
   ```
   در `web/.env.local`: `ENGINE_URL=http://127.0.0.1:8000` و `ENGINE_API_KEY` برابر همان `API_KEY` موتور.
5. **اجرای دائمی با systemd** (دو سرویس، تا بعد از ری‌استارت سرور خودکار بالا بیایند):
   - engine: `.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000` — **فقط یک پروسه** (بدون `--workers`)، چون صف ارسال داخل همین پروسه است و چند پروسه یعنی ایمیل تکراری.
   - web: `npm run start` (پورت 3000)
6. **Nginx**: زیردامنه را به `127.0.0.1:3000` بفرستید و با `certbot --nginx` HTTPS بگیرید. پورت 8000 را از بیرون باز نکنید؛ پنل خودش درخواست‌ها را به موتور می‌رساند.
7. **رمز پنل**: پنل فعلاً صفحه ورود ندارد؛ با Basic Auth در Nginx رمز بگذارید، ولی مسیرهای `/u/`، `/api/unsubscribe/` و `/_next/` را از رمز مستثنا کنید تا لینک لغو اشتراک برای گیرندگان باز شود.
8. **بکاپ**: کل داده‌ها در فایل `engine/data/app.db` است؛ روزانه از آن نسخه پشتیبان بگیرید.

اتصال به سایت اصلی (JS): همه امکانات از طریق API موتور در دسترس است (مستندات در `http://localhost:8000/docs`)، با هدر `X-API-Key`.

## ساختار کد پنل (web)

```
web/app/**/page.tsx      فقط یک import و رندر؛ هیچ منطقی ندارد
web/features/<feature>/  هر بخش پنل جداگانه
  components/            کامپوننت‌های کوچک همان بخش (مثلاً editor/ برای صفحه ویرایش)
  hooks/                 دریافت داده و اکشن‌ها (ذخیره، حذف، ارسال و...)
  lib/                   تایپ‌ها و ثابت‌های همان بخش
  index.ts               خروجی عمومی بخش
web/components/ui/       کامپوننت‌های پایه shadcn (Button با href به Link تبدیل می‌شود)
web/components/app/      کامپوننت‌های مشترک پنل (layout، شل، پیش‌نمایش ایمیل و...)
web/lib/                 API، ترجمه‌ها (i18n) و queries مشترک
web/routes/paths.ts      مسیر همه صفحه‌های پنل (PATHS) — برای Link، href و router.push
web/routes/api.ts        مسیر همه endpointهای موتور پایتون (API_ROUTES)
web/config/env.ts        تنظیمات سمت سرور (ENGINE_URL، ENGINE_API_KEY) — فقط route handler از آن استفاده می‌کند
web/config/metadata.ts   عنوان و توضیح سایت
web/config/navigation.ts آیتم‌های منوی کناری
```

هیچ مسیری نباید مستقیم در کد نوشته شود: `href={PATHS.CAMPAIGN(id)}`، `api(API_ROUTES.CAMPAIGNS.START(id))`. اگر صفحه یا endpoint جدیدی اضافه شد، اول آن را به `routes/` اضافه کنید. `config/env` عمداً در `@/config` export نمی‌شود تا هرگز وارد کد سمت مرورگر نشود.

بخش‌ها: `dashboard`، `discovery`، `companies`، `campaigns`، `templates`، `suppressions`، `unsubscribe`.
برای لینک همیشه از `Link` در Next.js یا `<Button href="...">` استفاده کنید، نه تگ `<a>`.
آیکن دکمه‌ها با prop داده می‌شود، نه به‌عنوان فرزند: `startIcon` (قبل از متن)، `endIcon` (بعد از متن) یا `icon` (دکمه فقط‌آیکن، همراه `aria-label` که tooltip هم می‌شود). «قبل/بعد» منطقی است و در راست‌به‌چپ و چپ‌به‌راست خودکار جابه‌جا می‌شود. برای فلش‌ها `directional` بگذارید تا در چپ‌به‌راست قرینه شوند، و برای حالت در حال انجام `loading`.
هر پوشه یک `index.ts` دارد و از بیرون فقط از همان مسیر import می‌شود، نه از تک‌تک فایل‌ها:
`import { Button, Input } from "@/components/ui"`، `import { PageHeader, Field } from "@/components/app"`، `import { api, useI18n } from "@/lib"`، و داخل یک بخش `from "../hooks"` یا `from "../lib"`. بخش‌ها همدیگر را فقط از ورودی عمومی‌شان import می‌کنند (مثلاً `@/features/templates`). فایل‌های داخل یک پوشه همدیگر را مستقیم (`./section`) import می‌کنند تا import چرخشی پیش نیاید.
قالب‌بندی کد با Prettier (حداکثر ۱۱۰ کاراکتر در هر خط): `npm run format` و بررسی با `npm run format:check`.

## ساختار کد موتور (engine)

```
engine/app/main.py            ساخت FastAPI و lifespan
engine/app/router.py          ثبت همه routeها در یک جا (عمومی / نیازمند X-API-Key)
engine/app/worker.py          حلقه‌های پس‌زمینه: اجرای جستجوها و ارسال کمپین‌ها
engine/app/config/            تنظیمات از engine/.env
engine/app/database/          اتصال، session، ارتقای خودکار جدول‌ها
engine/app/i18n/              کد پیام‌ها و خطاهای کددار (پنل ترجمه می‌کند)
engine/app/common/            ابزار مشترک: صفحه‌بندی، زمان، زبان‌ها، API key
engine/app/modules/<بخش>/     هر بخش جداگانه، هم‌نام بخش‌های پنل
  models.py                   جدول‌ها
  schemas.py                  ورودی/خروجی API
  service.py                  منطق
  router.py                   فقط endpointها؛ کار را به service می‌سپارد
```

بخش‌ها: `discovery` (منابع نقشه در `sources/`، استخراج ایمیل در `crawling/`، اجرای جستجو در `pipeline/`)، `companies` (ورود و خروجی Excel)، `campaigns`، `templates` (قالب‌های آماده در `builtin/`، هر نوع در یک فایل)، `suppressions`، `unsubscribe`، `meta`، `health` و `mailer` (ساخت و ارسال ایمیل).
`__init__.py` هر بخش فقط جدول‌هایش را export می‌کند (`from app.modules.companies import Company`)؛ service و router از فایل خودشان import می‌شوند تا import چرخشی بین بخش‌ها پیش نیاید. همه importها مطلق‌اند (`from app.…`).
قالب‌بندی و lint با ruff (حداکثر ۱۱۰ کاراکتر، مثل پنل): `pip install -r requirements-dev.txt`، سپس `ruff format app tests` و `ruff check app tests`.
